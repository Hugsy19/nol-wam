# NOL Scout — NOL World 回流票监控助手（Chrome MV3）

针对 **NOL World / Interpark onestop** 选座页的**座位级**余票监控与定位插件。

> **能做什么**：**页面即任务**（进了选座页，点一下就开始扫，不用先建任务）→ 收窄范围时
> **地图上实时圈出选中的区块**（v0.5.1）→ 持续扫描余票 →
> 精确到"哪个区域、第几排、第几号" → 弹窗 + 提示音提醒 → 给出**候选优先级队列**
> （首选 / 备份1 / 备份2）→ 在页面座位图上**把那个座位高亮出来**并滚到眼前
> （v0.4 起为像素级锚定，并自报标定精度）。
> **v0.6**：显示**选座 10 分钟倒计时**（起点取自会话令牌内嵌的服务器时刻），
> 剩 5 分钟 / 1 分钟分级告警，**到点自动停止扫描**；
> 轮询下限放宽到 800ms；「放大图」重做为可用的**全屏座位图**。
> **v0.6.1**：面板**默认贴在页面左边**（贴右会压住选座区域）——
> 可拖动、拖完记住、头部 `⇔` 一键贴左/贴右。
> **v0.7**：**验证码关卡助手**（只观察不代填）——出现验证码时自动聚焦输入框、
> 把剩余时间贴在验证码框正上方、记录这一关到底花了多久；
> 可选「验证码期自动开扫」让输入验证码的那 ~8 秒不空转。
> **不做什么**：不自动点选座位、不调用锁定接口、不提交订单、不识别验证码。最后那一下由你自己点。
>
> 原因很实在：韩国《공연법》第 14 条禁止用自动程序（매크로）购买演出票，NOL 商品页也写明检测到 macro 会取消订单并封号，
> 这类演出多绑定实名核验入场，损失不可逆。监控 + 定位 + 候选排序已经把「找到那张回流票」压到 1 秒内，
> 剩下的点击是安全区。
>
> 注：**模拟鼠标点击（合成事件 / CDP 注入）与直接调接口在法条下是同一回事**——
> 判定看的是"是否由程序代替人完成购买动作"，不看机制。所以这条线不动。

## 1. 安装

1. Chrome 打开 `chrome://extensions`
2. 右上角打开 **开发者模式**
3. **加载已解压的扩展程序** → 选择本目录 `extension/`
4. 改动源码后记得重新构建内容脚本：`node tools/build.mjs`，然后在扩展页点刷新

## 2. 使用流程

**① 进入选座页（唯一必要动作）**

在 NOL World 正常点"预订" → 排队 → 输入图形验证码 → 进入
`https://tickets.interpark.com/onestop/seat`。

插件会自动：
- 旁听到会话头 `x-onestop-session`（`onestop-hook.js` 只读旁听，零额外请求）
- **立刻开始 10 分钟倒计时**（起点 = 令牌末 10 位内嵌的服务器时刻，即排队放行那一秒；
  页面刷新也不断表，因为令牌不变）
- 构建座位目录（区块 / 区域 / 价位 / 每个座位的坐标）
- 在**页面左边**浮出面板（选座区域在中间/右侧，贴右会挡住座位图），并显示
  「**已检测到选座页：N 区块 / M 区域 / K 价位 · 点下面按钮即开始捡漏**」

> 面板位置：默认贴左，可以**拖标题栏**随便挪 —— 松手即记住（存 `chrome.storage.local.panelPos`），
> 刷新页面回到原地；头部 `⇔` 一键贴左 / 贴右切换。
> 拖出屏幕也不怕：坐标会被夹回可见区（纵向保证标题栏至少 120px 可抓）。

> **v0.5 起不再需要"新建监控任务"。** 你人已经在选座页了，页面本身就是任务的上下文
> —— 商品号 / 场馆号 / 场次都从页面自己的请求里旁听到，所以只需要一步操作。

**② 看「选座剩余时间」，点「▶ 开始捡漏扫描」**

默认范围是「全部价位 · 全部区域 · 1 张 · 不挑位置」——捡漏场景要的就是"有就行"。
想收窄就点「▸ 调整范围」：价位、区域、张数、位置偏好、轮询间隔
（档位 800 / 1000 / 1500 / 2000 / 2800ms；官网自身约 2.6~4.5s 刷一次，1000ms 以下算激进档，
命中更快但更容易被限流，面板会在日志里提醒）。

**倒计时怎么算的（不是猜的）**：

- `x-onestop-session` 形如 `26010474_M0000001661831791271752`，
  末 10 位是**排队放行那一秒的 Unix 时间**（抓包实测与 `waiting/api/rank` 放行时刻误差 0.45s）
- 时限 10 分钟来自站点自己的语言包：
  `"session_timer_expired_title": "Your 10-minute seat selection time has expired."`
- 终点由服务端权威判定：页面自己在轮询 GraphQL `ExpiredSession { isExpiredSession }`，
  插件只读旁听它（零额外请求）；本地钟归零但服务端刚说过"还没过期"时会给 45s 宽限，不误停
- 剩 5 分钟 / 剩 1 分钟分级告警（通知 + 面板变色 + 扩展徽标变红 `!`），
  **到点自动停止扫描**并弹通知；时间用完后想再扫必须重新排队进选座页

参数存在 `chrome.storage.local.scoutPrefs`，**页面面板与 popup 共用同一份**，两边改都即时生效。

**筛选时地图会实时标出选中的区块（v0.5.1）**：

- 面板底部那张座位图里，**选中的区块画蓝框 + 淡蓝底**，范围外的区块**整体压暗到 14%**；
- 地图下方一行图例直接给数字：`▣ 描边＝已选 12 个区块 · □ 压暗的 36 个不在范围内`；
- 筛选区里还有一行实时回显：`▣ 已选 12 / 48 区块 · 4,820 座（A구역 5块 · B구역 7块）`，
  每个区域/价位 chip 上也标了「N块」，点之前就能预判会圈中几块；
- 点 chip 只做**局部重绘**（chip 状态 + 回显 + 地图），不整块重建面板，所以连点几个也不卡。

> 口径上，面板说"选中了几块"和真正下发任务时"扫几块"用的是**同一份逻辑**
> （`lib/seat-prefs.js` 的 `resolveScope`），不存在"图上是这样、实际扫那样"。
> 顺带修掉一个埋得很深的 bug：档位筛选曾经拿**档位号**去比 `gradeCounts` 的**档位名**，
> 结果是"一选价位，目标区块就变成 0 个"——现在统一按 `block.gradeNos` 配对。

> 扫描**中途**改范围不会影响已经在跑的那条任务（任务启动时范围就固化了），
> 面板会明确提示「范围已改 —— 重启扫描后生效」。

popup 顶部的「捡漏扫描」区块里有同一个按钮，也可以从那里开始 / 停止和改范围。

**③ 命中时**

- Chrome 通知（文案带"页面已精确定位（N 座）"）+ 三声提示音
- 页面座位图上把命中座位元素高亮（黄圈脉冲 + 座号标签），并 `scrollIntoView` 滚到眼前
- 面板与 popup 出现 **候选优先级队列**：`首选 / 备份1 / 备份2`
  - 每条一行写明：区域 · 排 · 座号 · 价位（同时给韩元与人民币）· 连座数
  - 「定位」把该顺位跳到页面上，「复制」拿座号文本
  - 队列**只做排序与视觉定位**，页面上的选座点击始终由你自己完成

**④ 页面刷新 / 崩溃后**

只要还是**同一场演出**（商品号 + 场馆号都一致），插件会自动续扫；
换了演出、或你自己点过「停止扫描」，就不会自动开扫。
倒计时**不会**因为刷新而重置 —— 起点记在会话令牌里，刷新后续接剩余时间。

**⑤ 选座时间用完之后**

面板会显示「选座时间已结束」，正在跑的扫描**自动停止**，
再点「开始捡漏扫描」也会被拦下（提示重新排队）—— 因为这时会话在服务端已经死了，扫了也白扫。

**⑥ 换一场演出**

直接进入新演出的选座页 → 面板显示「已检测到选座页」→ 点开始即可。
不需要删除旧任务，任务 id 按「商品号:场馆号:场次」归一，反复点开始不会堆垃圾。

### 2.1 验证码关卡（v0.7，只观察不代填）

实测那一场：验证码图片在**计时开始后 25 秒**弹出，人工看图 + 输入 + 提交花了 **8.3 秒**——
这 8.3 秒是从选座 10 分钟里扣的。插件对它的态度是：**帮你看住时间，不替你输入。**

出现验证码时（`POST /onestop/api/captcha/image` 一旁听到就触发，比 DOM 还早一拍）：

- **自动聚焦输入框** —— 省掉"用眼睛找框 + 点一下"这两步（光标不写值、不派发事件、不提交）
- **贴身倒计时徽标** —— 贴在验证码框正上方：`⏱ 剩余 09:41 / 验证码已用 6.4s`，
  6 秒起变琥珀、12 秒起变红脉动；面板顶部有同一份口径的横幅
- **响铃 + 通知** —— 提醒你回到页面（卡 35 秒以上会再响一声，多半是输错了）
- **通关后记录耗时** —— 面板里多一行「上次验证码 ⏱ 8.3s」，让你知道这套流程真实吃掉多少秒
- **输错不清零** —— 本轮秒表重新起，累计时长照记，徽标继续走

**为什么不做自动识别 / 自动提交**（不是做不到，是不该做）：

1. 这就是站点的**反机器人闸门**——本场还带了滑块变体（`captchaPlugin`）。绕过它是最典型的 macro 证据，
   而 NOL 的处置是取消订单 + 封号，这些演出又多绑定实名核验入场，损失不可逆。
2. `captcha/verify` 挂着 **p9 签名**：想代提交就得把整条购买链路一起重放——那正是《공연법》14③
   与平台规则所指的行为。
3. 收益只有 8 秒（600 秒的 1.4%），风险却是账号级别。这笔账不划算。

> 那这 8 秒是不是白等？**不是**——只要扫描在跑，验证码期间照常在盯余票，
> 你通过的那一刻命中已经排在候选队列里了。想让它 guaranteed 生效，
> 在「▸ 调整范围 → 验证码关卡」里打开「**验证码期自动开扫**」（默认关，尊重"由我点开始"）。

> 商品页解析（popup 里的「商品页监控（兜底）」）只在**没有座位会话**时才需要用到：
> 它走商品页 RSC payload，只能看到档位级余票变化，不精确到座位。

## 3. 定位（v0.4 重做）

### 3.1 页面 DOM 契约（实测）

| 层 | 选择器 | 作用 | 实测（某场馆的控制台输出）|
|---|---|---|---|
| **座位层** | `[class*="SeatMap_seatGroup"]` → `<svg>` | 页面在这里**逐座位**画图，`viewBox` 就是座位坐标空间 | `viewBox="0 0 527 700"`，渲染 1883×2508 |
| 底图 | `[class*="SeatMap_placeImg"]` → `<img>` | 场馆轮廓 SVG | natural 527×700，与座位层 viewBox **完全一致** |
| 缩略图 | `[class*="MiniMap"]` → `<img>` | 右下角导航小图 | natural 527×700，但渲染只有 108×143 |

class 名带构建哈希（`SeatMap_seatGroup__dH6wd`），所以一律**前缀匹配**，不能写死。

**关键推论**：座位层 `viewBox` 与底图 `naturalWidth/Height` 相等 → 页面就是拿接口坐标
（`seatMeta.posLeft/posTop`）**直接画进座位层**的。这是能做到"像素级锚定"的前提。

> 上一版定位跑偏的三个原因（已修）：
> 1. 用 `渲染宽度 / viewBox宽度` 分别算 x、y 比例 —— 忽略了 svg 的 `preserveAspectRatio`，更忽略了页面自身施加的 transform（点区块放大时地图会带 transform）。改用 `getScreenCTM()` 才是精确换算。
> 2. 候选画布按"宽高比最接近座位包围盒"来挑，而**缩略图 MiniMap 的宽高比往往更接近** → 有可能锚到右下角那张小图上。现在 MiniMap 被显式排除。
> 3. 兜底逻辑把「座位包围盒拉满整张画布」，而接口坐标其实只占画布的一部分（见 3.2）。

### 3.2 一个容易踩的坑：虚拟座位会污染包围盒

同一个场馆的 `seatMeta` 里有两类坐标：

- **可见座位**（`isExposable: true`）—— 场馆 26000166：x 80.2~238.6，y 58.3~281.1，正好落在底图 `316×305` 内
- **非可见的"结算用"座位**（`isExposable: false`、`seatGrade: null`）—— 例如区块 `001:014` 那 100 个座位坐标在 x **353~380**，远在底图之外

拿后者算包围盒，整张图的比例就全错了。所以标定**只用 `isExposable` 的座位**（回归里有一条断言专门复现这个坑）。

### 3.3 三道定位

1. **锚定** — 座位层 svg 的 `getScreenCTM()`：user space ↔ 屏幕坐标，自动涵盖页面缩放/平移/父级 transform。
2. **校准** — 把页面**已经画出来的座位元素**（`rect / circle / path / …`）的屏幕坐标反算回 user space，
   与接口坐标拟合，解出 `sx / sy / dx / dy`（并自动尝试 x↔y 互换），用**残差 ÷ 座距**判断可信度：

   | 残差 | 判定 | 表现 |
   |---|---|---|
   | < 28% 座距 且 命中率 > 85% | **精确** | 直接高亮页面座位元素 |
   | < 85% | **粗略** | 仍可用，靠圆环标记 |
   | 其它 | **不可用** | 退回面板内置座位图 |

   页面只渲染当前放大区块时，会**逐区块比对**并挑出对得上的那一个；结果按场馆号缓存
   （`chrome.storage.local` 的 `locator:{placeCode}`），同场馆下次直接复用。
3. **落点** — 能对上具体座位元素 → 给**那个元素**加高亮类（`stroke` 脉冲，像素级）；对不上 → 黄色脉冲圆环兜底。
   两者同时画，方便互相印证。页面滚动/缩放后会按 user space 重算屏幕位置，标记不会跑偏。

### 3.4 面板上怎么读

面板（默认贴左）的「页面定位」一行，例如：

```
精确 · 残差 3%座距 · 页面座位 2474 / 命中匹配 1
```

- 显示 `待标定（启动监控后自动）` → 正常，启动后会自己算
- 显示 `标定失败` / `推定` → 点面板上的「**重新标定**」；仍然不行就看 3.5

### 3.5 还是不准？把诊断发我

**首选**：插件自己就能诊断。打开选座页 → 插件 popup → 座位页卡片里看「页面定位」一行，
或直接在面板日志里看「定位标定：…」。把这行连同 `chrome://extensions` → 插件的 Service Worker
控制台日志一起截给我就够。

**备用**：如果标定一直失败（说明页面不是逐座位渲染 DOM），在选座页 F12 粘贴下面这段，把输出发我——
它会把三层结构、座位层的 `viewBox/preserveAspectRatio/CTM`、以及**座位元素的标签与属性**都打出来：

```js
(() => {
  const cls = (el) => el?.getAttribute?.('class') || el?.className || null;
  const pick = (sel, deep) => {
    const w = document.querySelector(sel);
    if (!w) return null;
    const t = w.tagName.toLowerCase();
    const el = (t === 'svg' || t === 'img') ? w : w.querySelector(deep);
    if (!el) return { wrapClass: cls(w), inner: null };
    const r = el.getBoundingClientRect();
    const attrs = (x) => Object.fromEntries([...x.attributes].map((a) => [a.name, String(a.value).slice(0, 40)]));
    const tags = {};
    el.querySelectorAll('*').forEach((x) => { tags[x.tagName] = (tags[x.tagName] || 0) + 1; });
    return {
      wrapClass: cls(w), tag: el.tagName, cls: cls(el),
      viewBox: el.getAttribute?.('viewBox') || null,
      preserveAspectRatio: el.getAttribute?.('preserveAspectRatio') || null,
      natural: el.naturalWidth ? [el.naturalWidth, el.naturalHeight] : null,
      rect: [Math.round(r.width), Math.round(r.height)],
      ctm: (() => { const m = el.getScreenCTM?.(); return m ? [m.a, m.b, m.c, m.d, m.e, m.f].map((n) => +n.toFixed(4)) : null; })(),
      childTags: tags,
      firstChildren: [...el.children].slice(0, 6).map((x) => ({ tag: x.tagName, attrs: attrs(x) })),
      firstLeaves: [...el.querySelectorAll('rect,circle,ellipse,path,use,image,polygon')].slice(0, 4)
        .map((x) => ({ tag: x.tagName, attrs: attrs(x) })),
    };
  };
  const out = {
    href: location.href,
    seatLayer: pick('[class*="SeatMap_seatGroup"]', 'svg'),
    base: pick('[class*="SeatMap_placeImg"]', 'img,svg'),
    minimap: pick('[class*="MiniMap"]', 'img,svg'),
  };
  console.log(JSON.stringify(out, null, 1));
  copy(JSON.stringify(out));
  return out;
})()
```

> 注意：**DOM 结构**（3.1 那张表）任何一场演出的选座页都一样，随便哪场都能跑；
> 但**要验证坐标映射**必须挑**和抓包同一场**（否则没法和接口坐标对照）。
> 现在 v0.4 会自动标定并自报残差，所以通常**不需要**这段脚本，只有自动标定失败才需要。

### 关键设计

* **页面即任务**：任务不再由 popup 表单创建，而是由选座页自己按「当前页上下文 + 用户参数」构造
  （`buildAdHocTask`）。任务 id 固定为 `scout:{goodsCode}:{placeCode}:{playSeq}`，同一页面反复点开始
  只复用同一条。`adHoc: true` 的标记用于两件事：① 浏览器重启后**不**自动拉起（那时页面早就没了）；
  ② 页面刷新后只在**同一场演出**才自动续扫。
* **参数唯一来源**：`chrome.storage.local.scoutPrefs`。页面面板与 popup 都读写这一份，
  任何一边改动都会通过 `storage.onChanged` 同步到另一边。
* **候选优先级队列**：`matchSnapshot` 已按位置偏好打分排序，`labelRuns` 只把它切成
  「首选 / 备份1 / 备份2」。队列负责**排序与定位**，不负责点击——这是合规红线所在。
* **选区只有一处定义**：`resolveScope(prefs, catalog)` 同时喂给「地图高亮 + 选区回显」和
  「`targetBlocks` 真正要扫哪些块」。面板显示的和实际扫的走同一份代码，不会出现
  "图上圈了 A 区、后台却在扫全场"。区块与档位的配对一律用 `block.gradeNos`（档位号），
  绝不用 `gradeCounts` 的档位名——踩过坑，见 `blockGradeKeys` 的注释。
* **会话靠请求头传递**，不用 Cookie → 插件不伪造跨域请求，而是用 `onestop-hook.js` 在页面上下文里**只读旁听** `x-onestop-session`，再由内容脚本发同源请求。
* **10 分钟倒计时是"本地钟 + 服务端开关"**：锚点取 `x-onestop-session` 末 10 位（排队放行的服务器秒，
  抓包实测与 `waiting/api/rank` 放行时刻误差 0.45s），时限 10 分钟来自站点语言包；
  终点以页面自己轮询的 `ExpiredSession` 为准（插件只旁听，不额外发请求），
  本地钟归零但服务端刚否认过期时给 45s 宽限，防止误停。见 `lib/session-timer.js`。
* **座位序 = seatMeta 数组下标**，构建目录时**必须保持原序**，否则状态位会整体错位（`buildCatalog` 里有断言式注释）。
* **档位用"档位号"做键**，因为韩文名/英文名在不同接口不一致。
* **连座按真实几何判定**：同一 `rowIdx` 内、`x` 间距 ≤ 该行座距 × 1.35 才算连座（早期版本按数组下标相邻，站票区会误判）。
* **页面定位不靠"猜比例"**：先 `getScreenCTM()` 做精确换算，再用页面自己画出来的座位元素反解标定，
  最后用"残差 ÷ 座距"给出可信度——**能自证是否准**，而不是默默画歪。
* **标定只用可见座位**：`seatMeta` 里的非可见"结算用"座位坐标可能远在底图之外，混进来会把包围盒拉偏。

## 6. 已知限制

* **每轮扫描的区块数**：`seatStatus` 一次最多约 8~16 个区块。区块很多的场馆会拆成多个请求，单轮耗时会上升（插件会自动分块）。
* **座位很多的场馆**：超过 12000 个可见座位时，地图退化为「区块热力块」模式，不再逐座位画点（仍是精确数据，只是不画点）。
* **筛选时地图要重绘**：改动筛选条件只重绘地图那一小块（不重建整个面板），但座位数接近 12000 上限的场馆，
  连点 chip 仍可能有一帧的停顿——真到那个规模，地图本来就是热力块模式，重绘的是几十个矩形，不会卡。
* **缩放**：弹窗里的地图是静态渲染，命中时自动缩放到命中区块；**页面上的标记**会跟随页面滚动/缩放（按 user space 重算），但只有 500ms 一次的跟随频率。
* **页面定位依赖"页面把座位画成 DOM"**：若某版本改成整张位图渲染，会退化为「推定」精度（面板会如实显示）。
* **非零字符的其它含义**：目前"1=可购 / 0=不可购"有四条独立证据支持；若遇到反例，需要再抓一份"部分售出 + 完整下单"的包。
* **会话有效期**：选座会话 10 分钟（起点 = 排队放行时刻，见第 2 节）。过期后刷新座位页重走一次排队即可，插件会自动重新接管并重新计时。
* **倒计时精度**：锚点是服务器秒级时间戳，本地钟再用站点的 `getServerTime` 校准一次（毫秒级）；面板会显示校准偏移。若站点改了令牌格式（末 10 位不再是 Unix 秒），插件会退化为"首次观测"锚点并明确提示计时偏乐观。
